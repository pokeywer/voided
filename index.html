Instant run removes the console progress bar. Key checks, integrity checks, and tamper protection still run before the script starts.

VoidedX armor: Every copy is compiled to VM bytecode, then repacked in the VoidedX container: renamed internals, shuffled and masked segments, a compressed payload, and integrity checks. Every strength uses a single VM layer; High and Absolute add the Strong preset and heavier armor. Keep a readable backup and test before replacing a live vault. If compilation fails, the save is stopped and the existing vault stays unchanged.

Fast: Uses one VM layer, a light armor pass, and skips source string splitting to reduce execution work. It should run faster than Low, but is easier to analyze than the stronger presets.

Absolute: Uses the Strong preset, the heaviest armor pass, tamper checking, and extra string splitting. It is slower than High, can break scripts, and may create output too large to save in a vault. Test it first; no obfuscator can make client code impossible to inspect.

What this means: The server still checks access every time. The saved script can be read or changed on the executor, so use this only if faster repeat loading matters more than that risk. If file or hash support is missing, the loader downloads the script normally.

Scripts up to 128 KiB are stored as readable text; larger sources are compressed, not encrypted. Preview accepts source up to 4 MiB, but vault saves allow 2 MiB of source. Preview and download support output up to 32 MiB; previews over 1 MiB are download-only to keep the page responsive. A vault document has a safe serialized size limit of about 920 KiB, including its source, execution copy, and settings. Anyone who runs a client script can capture its delivered code, so never include passwords or private API keys.
