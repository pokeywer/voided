Flow: the outer loadstring still fetches /api/raw with no token. The response carries the inner loader only as Xorshift32 ciphertext. It opens with an ASCII VoidedX Loader banner; the gate URL, which embeds the live token, is stored as ciphertext under a per-build key instead of a readable literal, and every generated local name is randomized per build. Before the gate request and again before decrypting, the bootstrap checks the captured identity of string.byte/char/sub/gsub/match, table.concat, pcall, error, type, math.floor, loadstring/load, string.dump, game.HttpGet and, when present, bit32, getgenv/getfenv/setfenv, also compares the loadstring/load entries seen through getfenv(0) and getgenv() against the captured ones so a wrapper installed in only one channel is caught, and probes string.dump against both compile entries: a native load rejects a dumped Lua function while a Lua-level wrapper accepts it, which exposes hookfunction(loadstring, ...) shims that forward to the original. It refuses to continue if one was swapped or a debug hook is active, and it installs a debug.sethook function-count watchdog that rechecks the same references and its own hook identity for the first ~16M instructions or 10 seconds, marking itself in getgenv()._vxwd so the armor accepts it; both denials exit with "Voided: Doing this is not allowed." The plaintext is scrambled before sealing: locals and parameters are renamed, string literals move into a per-run encoded table decoded in memory, and the body is minified, so only the -- VoidedX Loader credit comment stays readable. Compilation prefers whichever of loadstring/load is still native and, when the executor supports a function reader, feeds the decode entry 4096-byte chunks instead of one string, so an argument logger on the compile entry sees fragments. A separate token-check request releases the HMAC-derived seed after the token, network binding, vault version, and key checks pass, so a captured response body cannot be decrypted offline. /api/verify returns a random payload seed, a shuffled chunk order, a CRC32, and a 16-hex trace; /api/payload returns only the shuffled, encrypted chunks. Capturing either response alone is not enough. The runtime compares game.HttpGet, loadstring/load, HttpService.JSONDecode, string.char/byte/sub, table.concat, pcall, rawequal, debug.info, print, tostring/tonumber/type/next/ipairs/setmetatable/rawset, math.floor, string.format/rep/gsub/match, game.GetService, HttpService.UrlEncode, and task.wait/spawn against references captured at start. Before the payload is requested it also publishes a decoy getgenv().VoidedX table whose unlock/bypass/dump helpers and unknown-field reads report honeypot_triggered, a blocking flag. Swapped functions are reported to /api/integrity, and high-confidence reports mark the one-use ticket blocked so /api/payload refuses delivery. Every payload carries a --[[vx:TRACE]] watermark; loaderDeliveries/{trace} maps it to the vault, player, key issue, and delivery IP. The fast-load plaintext cache is bypassed for shielded payloads because an on-disk plaintext copy defeats the protection. Set LOADER_TOKEN_IP_BIND=0 if legitimate executor HTTP egress IPs change between the bootstrap and gate requests; set LOADER_TOKEN_SECRET to a random value of at least 32 bytes for stable signing and seed derivation. These checks raise the cost of runtime dumping and make leaks attributable, but they are not DRM: a hook installed before the loader starts, a patched executor, or a loader modified to strip checks can still capture executed code.

This patch uses the bundled Prometheus fork locally in the browser and then repacks its output in the VoidedX armor container, so delivered copies do not carry Prometheus's recognizable layout. It does not include the separate Prometheus website interface.

The strength selector offers Fast, Low, Medium, High, and Absolute in Luau mode. The Prometheus fork starts in a module worker and compiles the script to VM bytecode, then lua-voidedx-armor.js repacks that output: the watermark is rebuilt from split literals, helper names are renamed, decoys and opaque guards are added, and the payload is LZSS-compressed, masked in passes, split into shuffled segments, and wrapped in a randomized loader with integrity checks and a Roblox gate. The loader itself is emitted unformatted: comments are stripped, statements are packed with minimal gaps, and line breaks land at random so the file reads like raw VM output. Every armor level now emits the debug-hook guard, which accepts a hook only when getgenv()._vxwd names it: the bootstrap watchdog passes, a foreign hook or stale marker is denied. Nested containers compile from a 4096-byte reader and prefer whichever of loadstring/load is still native. Each delivered copy now starts with an ASCII VOIDEDX banner and 16 to 29 inert `do ... end` junk blocks, followed by the `-- VoidedX` marker. The junk is regenerated per build from confusable identifiers (l/I/1, O/0/o, S/5, Z/2, B/8, G/6, q/9), randomized block shapes, number and escape soup, and gibberish comments, so it reads as noise and no two builds share the same preamble. Fast uses the Weak preset; Low and Medium use Medium; High and Absolute use Strong. Every level keeps one Prometheus VM layer: a second Vmify pass over the first VM's bytecode corrupted output in every interpreter we tested. Depth comes from nested VoidedX containers instead (Fast 1, Low 2, Medium and High 3, Absolute 4), capped by payload size so large copies stay storable. Low and above add the Sigil Cipher (integer-exact string sealing), a seed-bound VoidedX watermark, decoys, and anti-tamper. The loader also rejects a `pcall` that swallows errors. Absolute also turns on tamper checking and extra string splitting. Auto uses High up to 16 KiB of UTF-8 source and Low above. The page rewrites bare `#` length operators in the generated decoder to a safe helper so executors that return userdata objects do not crash. Obfuscation failures stop saving and preserve the existing vault. Source up to 128 KiB is stored as readable text in Firestore for owner audits; larger source is gzip-base64 compressed to preserve document space, not encrypted. Older plain-text and gzip-base64 records remain supported. The execution copy is stored as plain text when it is ASCII and smaller than its gzip-base64 form, otherwise gzip-base64; the API decompresses base64 records for delivery. Browser previews accept source up to 4 MiB and generated output up to 32 MiB; saving source to a vault remains capped at 2 MiB. Output above 1 MiB is download-only to avoid freezing the page. Saved outputs are capped at 4 MiB, and the estimated Firestore document cap is about 870 KiB, so the document cap can be reached first. Obfuscation jobs may take several minutes; Absolute is the slowest and most fragile. Unkeyed raw loaders fetch the generated body rather than embedding a second copy inside the bootstrap. Existing /api/raw, /api/verify, and /api/payload routes deliver it. Client code can still be captured and analyzed while running.

Based on Prometheus by Elias Oelschner, https://github.com/prometheus-lua/Prometheus. See LICENSE-PROMETHEUS.txt.

Obfuscation profile 17 marks the current container: an ASCII VOIDEDX banner and a per-build block of inert, confusable-identifier junk on top, a VoidedX marker with an intentionally unformatted loader body, the integer-exact Sigil Cipher replacing the stock string step, a tolerant anti-tamper probe suite plus a loader-level `pcall` guard, a debug-hook guard at every armor level that honors the bootstrap's getgenv()._vxwd marker, reader-mode compilation in nested containers, and a single Prometheus VM layer with nested VoidedX containers at every strength. Profile 17 replaces the fixed container codec with a polymorphic one: each build chooses its own byte mixer (add, subtract, or affine with a modular inverse), its own 32-bit state-chain multiplier, increment and content-mix weights, its own keystream shift, its own LZSS token split point, minimum match length, offset byte order, offset bias and flush sizes, its own identifier style, and its own segment permutation, which is rebuilt at runtime from a seed instead of being shipped as a table. The keystream also mixes the previous ciphertext byte and the absolute stream position, so one segment cannot be decoded in isolation, and two builds of the same script share no constant, no identifier and no decode shape; a deobfuscator written for one file does not work on the next. Vaults saved before it, including the profile 16 build, the profile 15 build, the profile 14 build, the two-layer High/Absolute VM build, bytecode-VM (profile 10), unarmored copies (profile 11), and the earlier armor (profile 12), carry an older profile number. The VM keeps the Prometheus opcode set because the engine is a prebuilt binary with no source to renumber it, so the armor hides the engine layout but a recognizable bytecode dump can still be disassembled with the Prometheus tooling. Open and save older vaults again to regenerate the execution copy. Keep a backup and try the output in a private test place before broad use. A saved vault document is capped at an estimated 870 KiB to leave headroom under Firestore's document-size limit.

DISCORD /obfuscate VOID TOKENS

/obfuscate now gives each Discord user 5 void tokens and a private link of the form https://voidedx.vercel.app/obfuscation?vx=<token>; /obfuscationvx=<token> is rewritten to the same page. Upload a .lua/.txt file or paste code in the command, or open the link and paste it there. Each successful obfuscation spends one token, and the page can also save the generated copy to a new vault.

Upload or replace these files together:

  api/_obfuscationSessions.js       (new) token creation, reuse, expiry, atomic spend
  api/_route-obfuscation-session.js (new) GET/POST /api/obfuscation-session
  api/_route-discord-interactions.js (replaced) /obfuscate creates the token link
  api/_discordConfig.js             (replaced) command description and option text
  api/[...path].js                  (replaced) registers the obfuscation-session route
  obfuscation.html                  (new) token page
  obfuscation.js                    (new) page logic, obfuscation, download, vault save
  vercel.json                       (replaced) adds the /obfuscationvx= rewrite

New Firestore collections: obfuscationSessions/{token} stores the preloaded source, level, filename, credits, and expiry; obfuscationSessionOwners/{discordUserId} points to the user's current token so a new /obfuscate reuses the link while credits remain. Tokens are 24-byte base64url values, last 7 days, and spending uses a transaction so the fifth token cannot be double-spent. A user has one active link at a time; issuing a new token deletes the previous session document. The link is bearer-style: anyone who has it can spend its remaining tokens until they run out or the session expires. Vault saving uses anonymous Firebase auth and the same record shape as the Creator Panel, including the 5-vault limit and 10-hour auto-delete, and the vault is owned by that browser session.

Discord command registration is unchanged for names and options; only the /obfuscate description and the file/code help text changed, so the existing registered command still works and re-registering is optional.

The link page obfuscates in the browser with the same engine (lua-medium.js plus lua-voidedx-armor.js and the prometheus-engine assets) used by the Creator Panel, so those files must be deployed with the page.
